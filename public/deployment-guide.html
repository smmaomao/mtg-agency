一、系统架构

MTG Agency 是一套广告归因回传（Postback / S2S）转发服务，提供对外回传接收与管理后台能力，共用同一个数据库。

  • 开发语言 / 框架：Next.js（App Router）+ React 19 + TypeScript
  • 数据库：PostgreSQL（Supabase，事务池 6543 端口）
数据流：s2s 回传 → /install|/event → 先落库 callback_logs(pending) → 转发 postback.mintegral.net → 回写日志状态

二、服务器部署（Vercel）

项目已包含 vercel.json，推荐部署到 Vercel。本地自托管则用 next build + next start。

部署步骤

  1. 将代码推送到 Git 仓库（已对接 Vercel 自动部署）。
  2. 在 Vercel 项目 Settings → Environment Variables 配置以下变量（见下表）。
  3. 触发 Deploy，等待 npm run build 成功。
  4. 部署完成后，先用默认管理员登录后台核对（默认账号见下方说明）。

* 注意：Vercel 和 Supabase 数据库要选同一个地区（都是新加坡或者香港），这样才能降低延迟。

Vercel 和 Supabase 都是免费的（一些服务需要收费，免费的对于我们来说足够了），且运维自动化。如果想通过自己服务器来部署也是可以的，对接具体的服务器运营商。

环境变量

变量必填说明
DATABASE_URL否*PostgreSQL 连接串（若设置则优先使用；Supabase 事务池用 6543 端口）
DB_HOST / DB_PORT / DB_NAME / DB_USER / DB_PASSWORD否*分项数据库连接；与 DATABASE_URL 二选一即可，两者同时配置时优先用 DATABASE_URL
JWT_SECRET是JWT 签名密钥，生产务必设置为强随机值
MOCK_FORWARD否仅本地开发设为 true；线上不要配置

* 数据库连接二选一：设置 DATABASE_URL 即可，或设置 DB_HOST / DB_PORT / DB_NAME / DB_USER / DB_PASSWORD 也能连接（如本地 docker Supabase 默认 54322），无需 DATABASE_URL。

三、业务配置流程

在后台按以下顺序配置，最终生成供回传归因使用的 campuuid（包映射）：

① 客户管理
→
② 产品管理
→
③ 包体管理
→
④ 包映射配置

1客户管理（/dashboard/customers）

录入广告主 / 代理客户基本信息，作为后续数据的归属根节点。

  • 名称（必填）：客户名称。
  • 联系人、联系电话、邮箱、开通日期、备注（选填）。

2产品管理（/dashboard/products）

在客户下创建推广产品。

  • 归属客户（必填）：关联第 ① 步的客户。
  • 产品名称（必填）、产品类型（默认 game）、描述、地区、图标、备注。

3包体管理（/dashboard/packages）

在产品的下创建具体 App 包体。

  • 归属产品（必填）：关联第 ② 步的产品。
  • 包体名称（必填）、平台（android/ios）、版本、下载地址、包名（package_name）、落地页地址。

4包映射配置（/dashboard/dsp-mapping）

将包体映射到某个 DSP / 渠道，并生成用于回传归因的 campuuid。这是业务链路的最终产出。

  • 包体（必填）：关联第 ③ 步的包体。
  • DSP 名称（必填，如 Mintegral）、渠道名、DSP 侧包 ID、落地页。
  • campuuid：广告单元 ID，下游归因与回传匹配的关键标志。
  • 状态（active / 停用）、备注。
图：包映射配置页面（/dashboard/dsp-mapping）
⚠️ campuuid 为动态后缀：我方提供的 campuuid 带动态后缀，例如 game_ios_us_0713_wbl_* —— 刚开始可能是 game_ios_us_0713_wbl_cpi， 过一段时间会变成 game_ios_us_0713_wbl_cpm。对接方（MMP / 广告主）需保存当时 clickid 对应的 campuuid，在回传时原样带回，否则归因会失败。
